# 销售话术分析与入库规范

版本:v0.1  日期:2026-11-09
资料:`Tutor Luna 场景话术.pdf`(整理稿见 `knowledge/raw/tutor-luna-场景话术-整理稿.md`)
结论先行:**这份话术不能原样整体入库。** 它既有可用的产品事实,也有需要合规审核的承诺性表述,还有前后矛盾的地方。建议先按本文拆分、审核,再入库。

## 1. 我们现在知道的业务

| 项 | 内容(来自话术) |
|---|---|
| 产品 | Tutor Luna:1v1 AI 外教英语口语课,儿童,基于剑桥 Power Up 教材 |
| 体验课 | 一个单元共 4 节,每节 15–20 分钟,有效期 4 天,话术称"价值 99 元";不需要预约,下载 APP 即可上课 |
| 体验课准备 | 销售"植入课程",用户用报名手机号登录 APP;仅支持安卓/苹果的平板和手机,不支持电脑/学习机 |
| 正式课 | 学霸包 3699 元/288 节(三级别),培优包 2699 元/192 节(双级别);每节 25 分钟;每周一解锁四节 |
| 成交方式 | 在**抖音平台下单**;有 1100 元优惠券和抖音满减,话术称学霸包实付 2250 元;赠实物礼品 |
| 退款 | 7 天无理由试学期,话术称"全额免责退款""当天到账""抖音极速秒退" |
| 钩子 | 上完第一节课送"全套 KET 备考资料"或"60 套原版绘本+40 节外教环游记" |

**对产品设计的几个直接影响**
1. 成交和退款都在抖音平台完成,**我们的系统不收款**。关单 = 引导用户去抖音下单,并跟进是否下单。需要抖音订单状态作为数据来源。
2. "植入课程"是销售的人工动作。登录检测(话术里"没看到咱们的账号")说明课程后台能判断"用户是否已登录 APP",这是待到课阶段最关键的状态数据。
3. 报名时有一个"信息表"(话术"把上方的信息填写一下"),其中包含孩子的英语基础。这意味着**挖需的一部分信息已在进线时收集**,需要确认表单内容和数据落在哪里。

## 2. 话术与 8 个阶段的对应

| 阶段 | 话术覆盖情况 | 已有话术 | 缺口 |
|---|---|---|---|
| 1 进线校验 | ❌ 没有 | — | 校验规则、不通过的话术 |
| 2 打标签 | ❌ 没有(属系统动作) | — | 标签清单 |
| 3 破冰 | ✅ 较少 | 进线首次打招呼 | 用户不回复时的追发话术 |
| 4 挖需 | ❌ 基本没有 | 仅"根据孩子英语基础匹配级别" | **缺少提问话术**:孩子年龄/年级、英语基础、学习目标、家长顾虑 |
| 5 邀约 | ✅ | 促建联、确定体验课时间、软件下载方式 | 用户拒绝/犹豫时的话术 |
| 6 待到课 | ✅ 较多 | 催下载(2 条)、催到课(6 条) | 缺时间节点(什么时候发哪一条)、缺"已下载未登录"以外的异常(设备不支持、麦克风权限、登录失败) |
| 7 到课未完课回访 | ⚠️ 单薄 | 仅 1 条 | 多次回访、不同卡点(听不懂、没时间、设备问题)的分流话术 |
| 8 完课转化关单 | ✅ 最多 | 课后反馈、问价格、12 类异议、关单报价 | 抖音下单操作指引、下单后确认、未成交跟进、议价边界、退款流程话术 |

**缺口判断**:AI 要做"挖需"和"邀约",但现有话术几乎只覆盖"催"和"答异议"。挖需话术需要销售补充,否则 AI 只能自己发挥,风险较高。

## 3. 话术的四类用途(决定放哪里)

| 类型 | 本份话术中的内容 | 放哪里 |
|---|---|---|
| A 事实资料 | 体验课规格(4 节/15–20 分钟/4 天有效期)、设备要求、下载方式、教材来源、课程结构(四节课设置、4 阶闭环)、正式课规格(级别、节数、每周解锁) | **知识库(RAG)**,AI 回答的事实依据 |
| B 异议策略 | 12 类异议(时间短/死板/不纠错/反应慢/听不懂/对比真人/没测评/语法/无作业/不能重复学/全英/礼品折现) | **知识库(RAG)**,按异议类型检索,作为"应对思路",AI 改写后使用,不照搬 |
| C 主动触达话术 | 催下载、催到课(6 条)、到课未完课、课后反馈 | **模块 E 的步骤配置**(按时间/事件主动发),不放 RAG |
| D 价格优惠 | 学霸包/培优包价格、1100 优惠券、2250 实付、赠品 | **结构化价格表**,不放 RAG;AI 报价只能读价格表 |

另外,"进线首次打招呼"和"促建联"属于模块 A/E 的固定话术,也不放 RAG。

## 4. 需要先处理的风险与矛盾(请相关方确认)

### 4.1 前后矛盾(必须在入库前统一)
| # | 内容 | 矛盾点 |
|---|---|---|
| C1 | 异议 2、异议 3 说"**下周**会完成大型 AI 能力升级";关单报价说"正式课**已经完成**全量用户的新版升级" | 同一份话术里升级是"未来"还是"已完成"互相冲突。AI 若学到会随机说其中一个 |
| C2 | 异议 2、4 说体验课用"腾讯的大模型",正式课用"自研大模型";第 7 页技术亮点图写意图识别基于 Qwen3-32B、教学话术由 DeepSeek V4.1 生成 | "自研"与图上第三方模型的表述不一致,也不应让 AI 向用户披露模型来源 |
| C3 | 第 7 页图标题为"LingoAce Luna Tutor",正文为"Tutor Luna" | 品牌/产品名称写法不统一,需要确定对外名称 |
| C4 | 问价格:培优包单价 14.05;2699÷192≈14.06 | 小数位核对 |
| C5 | 关单报价:学霸包原价 3699,1100 元券后应为 2599,话术称实付 2250(还有抖音满减) | 2250 的构成需要价格表明确,否则 AI 会算错或乱报 |
| C6 | 体验课"价值 99 元",而用户领取通常是免费或低价 | 需确认对用户的真实说法,避免虚构价值 |

### 4.2 合规与承诺风险(建议法务/运营审核)
| # | 内容 | 风险 | 建议 |
|---|---|---|---|
| R1 | "当天就可以退款到账""抖音极速秒退""全额免责办理退款" | 对退款时效和条件作了确定承诺 | 以抖音平台和公司退款政策为准,AI 只复述政策原文,不自行承诺到账时间 |
| R2 | "不合适咱们抖音平台下单,就在抖音平台申请退款"(异议 2 的原话) | 表述逻辑混乱,可能误导用户先下单再退款 | 重写 |
| R3 | "您收到礼品实在用不上,挂咸鱼卖了也能卖三四百块钱" | 暗示礼品可转卖并给出估值 | 删除,不入库 |
| R4 | "86%的小朋友完成第一节课,平均开口次数 57 次" | 写死的统计数字,可能与事实不符,且需要数据来源 | 改为由数据后台动态生成,否则不入库 |
| R5 | "公司想在升级前占据一波 AI 外教的市场,所以价格更低" | 带营销施压和内部信息 | 不入库 |
| R6 | "这也是新课标重点要求的能力" | 引用政策需有依据 | 核实后保留或删除 |
| R7 | "性价比更高""AI 反应慢的根源在于腾讯服务器链路延迟""约 1 秒延迟" | 比较性与技术性表述,缺少依据,且在对外沟通中归因第三方 | 删除归因,延迟数据需产品确认后再用 |
| R8 | "课程会越学越智能""根据每个孩子不同基础进行个性化教学" | 能力描述,需与产品实际一致 | 产品确认 |
| R9 | 话术中销售以"Tutor Luna 的老师"自称 | 若由 AI 回复,是否需要告知用户这是 AI,存在合规与体验两方面问题 | **需要产品和法务决策**(见 §6) |
| R10 | 赠品条件("上完第一节课送 KET 资料或绘本")、"三种实物礼品"的具体内容 | 兑现条件不清可能引发投诉 | 明确赠品清单和兑现规则 |

## 5. 入库规范

### 5.1 切分
- 事实资料(A 类):每个主题一条(如"设备要求""体验课规格""课程结构"),每条独立、可单独回答问题。
- 异议策略(B 类):每个异议一条,保留"家长常见说法 → 应对要点 → 参考话术",**长文拆成要点**。原话术过长且口语冗余,直接给模型容易产生冗长回复。
- 一条内容只讲一件事,避免把"事实+承诺+促单"混在一起。

### 5.2 每条的元数据
| 字段 | 说明 |
|---|---|
| 类型 | 事实 / 异议策略 |
| 阶段 | 适用阶段(如 6、7、8) |
| 异议类型 | 仅 B 类 |
| 适用级别/课包 | 体验课 / 学霸包 / 培优包 |
| 生效/失效日期 | 价格、活动类必填 |
| 来源与版本 | 如"销售话术 v1" |
| 合规状态 | 未审核 / 已审核 / 禁用 |
| 敏感标记 | 涉及退款、价格、承诺的条目标记,AI 回答时必须原文引用,或转人工 |

### 5.3 检索规则
- 按用户当前阶段过滤:破冰阶段不检索关单、报价类内容。
- 涉及退款、价格、赠品的问题,只引用已审核条目;检索不到就转人工。
- 异议策略类条目只用于"生成思路",输出由模型按用户的原话改写,并通过输出审核(禁止承诺词表)。

### 5.4 入库前清单
1. 标出本文 §4 的矛盾,由产品/运营确认唯一口径。
2. §4.2 中建议删除的条目不入库。
3. 把价格移出话术,建立价格表。
4. 补充缺口话术(挖需、未到课异常、多次回访、抖音下单指引)。
5. 合规审核通过后,标记"已审核"再发布。

## 6. 需要产品拍板的新问题

| # | 问题 | 选项 |
|---|---|---|
| Q1 | AI 回复是否需要向用户明示"这是 AI"? | A 明示(合规稳妥,但可能影响转化) / B 以"助教"身份但不隐瞒 / C 不明示(不建议) |
| Q2 | 销售人设:统一为"Luna 老师"还是各销售保留自己的名字? | 影响话术变量和一致性 |
| Q3 | 价格、优惠由谁维护?变更多久生效? | 建议运营维护价格表,AI 只读 |
| Q4 | 抖音订单状态能否接入? | 否则关单后无法判断是否成交,也无法停止催单 |
| Q5 | "植入课程""开通体验课"是人工还是系统自动? | 影响邀约到待到课之间的衔接 |
| Q6 | 退款类问题 AI 能答到什么程度? | 建议只复述政策,具体办理转人工 |
| Q7 | 对外产品名称:Tutor Luna 还是 LingoAce Luna Tutor? | 统一后清洗全部资料 |
| Q8 | 第 7 页技术亮点图是否可以直接对用户使用?其中模型名称等是否属于内部信息 | 建议不对用户披露 |
| Q9 | 进线时的信息表包含哪些字段,数据存在哪里? | 影响挖需阶段能做什么 |

## 7. 下一步建议

1. 把 §4 的矛盾与风险发给运营负责人和法务,请他们给出统一口径。
2. 请销售补充四类缺口话术:挖需提问、未到课异常处理、多次回访、抖音下单指引。
3. 我根据确认后的口径,再把整理稿拆成"事实知识条目 + 异议策略条目 + 主动触达话术 + 价格表",并同步更新 PRD、流程图、技术方案、后台说明和问卷。
